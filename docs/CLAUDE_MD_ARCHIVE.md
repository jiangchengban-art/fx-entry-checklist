#### 機能詳細
- **ペア選択（S25で分類表示化）**: ツールバーの「通貨ペア選択」ドロップダウンでペアを選択。プリセット28ペアは 5 つのグループ（株価先物・仮想通貨・金銀原油・USD系・その他通貨）に分類され、プルダウンは `<optgroup>` で表示。存在しなければ自動作成、存在すれば前回選択した上位足・エントリー足が復元される。選択中のペアID は localStorage（`mochipoyo_market_view_selected`）に保存
- **カスタムペア**: 「その他（自由入力）」を選ぶと入力欄が表示。入力値を確定すると登録・選択される
- **全銘柄の自動生成（S25新規）**: 🔭一覧タブがボード選択の履歴に依存せずプリセット全28銘柄を巡回対象とするため、`loadMarket()` がストレージ読み込み時に未作成ペアを自動生成。ボード側の `selectPair()` 挙動には影響しない（ボードは従来通り1ペアずつ選択・記録）
- **上位足・エントリー足の選択（セッション19で新規）**: カード上の2つのプルダウン
  - **上位足**: 週足 / 日足 / 4時間足 / 1時間足 から選択
  - **エントリー足**: 5分足 / 15分足 / 1時間足 / 4時間足 から選択
  - 選択するとペア属性（`tfHigher` / `tfEntry`）として即保存
- **根拠チェック（セッション20で新規、S37で RCI/MACD 選択肢変更、S38でエントリーFibo追加、S46で「待ち」追加）**: 各時間足のプルダウン下に8行が並ぶ。上位足とエントリー足で独立した値を保持
  - **グランビル**: 1 / 2 / ❌
  - **RCI**: 短期/中期/長期（各：上限 / 60↑ / 60↓ / 下限 / ⏳待ち / ❌）を3本独立で記録
  - **MACD**: RD(転換) / HD(継続) / ⏳RD待ち / ⏳HD待ち / ❌（S37: 表示名変更。S46: 「待ち」を追加）
  - **ラウンドナンバー**: 有 / 無 / ❌
  - **ロールリバーサル**: 確認 / 未確認 / ❌
  - **エントリーFibo（S38）**: 23% / 38% / 50% / 61% / 78% / ❌ — エントリー足の1波のどのフィボナッチ水準でエントリーしたかを記録。小数点は省略
  - 選択値は ペア属性（`checksHigher` / `checksEntry`）として即保存。同じボタンを再タップで未選択に戻せる。`MV_TF_CHECKS` 配列に1行足すだけで新項目が両時間足に自動反映される（拡張性）
- **アラート発生足**: カード上に「1H / 4H / D / W」の4つのバッジが常時表示。それぞれ独立にON/OFFをタップ切替、ONにした瞬間の日時を記録
- **判定3択**: 「✅エントリー / ⏸保留 / ⏭スルー」のトグル。判定を新たに設定するたびに `judgeLog` に記録（統計の元データ）
- **チェックリストへのジャンプボタン**: 「📝 チェックリストへ」ボタンで🎯トレード内のチェックセクションにスムーススクロール移動
- **データ独立性**: 専用キー `mochipoyo_market_view_v1` (ペア・S19で `tfHigher` / `tfEntry` 追加・`judgeLog`) + `mochipoyo_market_view_selected` (選択中ペアID) に保存。トレード記録（`mochipoyo_trades_v1`）とCSVには一切影響しない
- **アラート発生足別の判定統計（S18で追加）**: 📚振り返りタブの統計サマリー内に「アラート発生足別の判定統計」セクションを追加。`judgeLog` を時間足ごとに集計し、各時間足で発生したアラート後の ✅エントリー/⏸保留/⏭スルー 件数を表示（同時に複数の足がONだった場合はそれぞれの足のカウントに重複加算）
- **自動マイグレーション**: 
  - S12形式（pairs が文字列配列）→ S14形式（オブジェクト配列＋id・alertTf・judge）：既存スナップショット・履歴保持、watchId 付け替え
  - S14形式（ペア＋時間足ごとの複数カード）→ S17形式（ペア単位）：同名ペアが複数あれば統合、スナップショット履歴は失われない
  - S17形式（単一 alertTf 文字列）→ S18形式（`alerts.{h1,h4,d,w}` オブジェクト）：一致する時間足があれば ON として引き継ぐ（発生日時は不明なため空）
- **拡張性**: `MV_TFS` に1行足せば記録する時間足を追加でき、カード・履歴すべてに自動反映。アラート発生足は `MV_ALERT_TFS` で管理
- ⚠️ **S12〜14で削除された機能**: 記録モーダル、時間足ごとのメモ入力欄、AI分析コピペ連携（プロンプト自動生成・コピー機能）。過去の設計は `docs/CHANGELOG_ARCHIVE.md` を参照

### 8. トレード結果の記録（旧：3分割エントリーと決済記録、セッション22で追加 → **S54で全廃・結果タグ＋円建て損益方式に完全置換**）

⚠️ **この節が扱っていた仕組み（建玉ブロック・3分割決済モーダル・RR計算・合成RR・枚目別/損切り根拠別の成績）はS54で完全に削除された。** ユーザーの実運用フローが変わり、価格ベースのRR計算ではなく結果タグ（REG/BIG/MAX/微益/建値決済/損切/その他）と円建ての損益額で記録する方式に置き換えたいという明示的な指示による。以下は歴史的経緯として残す。詳細は「3. トレード記録フォーム」の現行仕様を参照。

**旧・実運用ルール（〜S53、参考）**:
- エントリーは常に3分割（例：3万円リスクなら1万円×3）。3枚とも同一価格・同時エントリー
- 各枚の計画利確は 2:1 / 3:1 / 4:1。ただし相場次第で RCI上限・下限／直近高値／ラウンドナンバーで早期利確することもある
- 1枚目を利確したら残り2枚の損切りを建値に上げる（建値で戻されたら RR 0.00 → `breakeven` 根拠で記録）
- 損切り位置は 直近安値/高値をカバー か 直近の波のフィボナッチ161%をカバー

**旧データモデル（S54で削除）**: `entryPrice`/`slPrice`/`slBasis`/`splitCount`/`exits[]`（`slot`付き=実玉・`slot`なし=参考到達ポイント）、合成RR＝3枚のRRの平均（`tradeNetRR()`）。旧・削除済み関数：`calcRR()`/`fmtRR()`/`tradeExits()`/`isSplitTrade()`/`slotExits()`/`tradeNetRR()`/`planTargetPrices()`/`decimals()`、決済モーダル関連の `openExitModal()`/`renderExitAll/Risk/Slots/Rows()`/`exitRowInner()`/`renderExitSum()`/`fillRemainingSlots()`一式。

**S54の新方式（現行）:**
- トレードに `manualAlertAt`/`manualAlertTf`（フォーム内独立のアラート記録）、`resultTag`（結果タグ）、`resultOtherReason`（その他の理由）、`pnlAmount`（円、符号付き）、`beTouch`（建値タッチ）、`images.{entry,higher,others[]}`（Firebase StorageのURL）を追加
- `resultTag` は `''|'reg'|'big'|'max'|'small_profit'|'breakeven'|'stoploss'|'other'` の単一値。`other` のときのみ `resultOtherReason` を使う
- 画像アップロードは Firebase Storage の REST API（`POST https://firebasestorage.googleapis.com/v0/b/{bucket}/o?uploadType=media&name={path}`）へ**fetchのみ**で行う（`uploadChartImage()`）。**単一ファイル・CDN依存なしの原則を守るため Firebase JS SDK は使わない**。bucket・API Keyは⚙設定タブの「🖼 チャート画像（Firebase Storage）」セクションで入力し `mochipoyo_firebase_config_v1` に保存
- 統計タブは「合計損益」「平均損益」「勝率（`pnlAmount > 0`）」「結果タグ別の成績」「建値タッチ別の成績」に置換（詳細は「5. 統計サマリー」参照）
- 旧CSV列（`entryPrice`/`slPrice`/`slBasis`/`splitCount`/`exits`）は完全撤去し、新列（`manualAlertAt`/`manualAlertTf`/`resultTag`/`resultOtherReason`/`pnlAmount`/`beTouch`/`imgEntry`/`imgHigher`/`imgOthers`）に置換（ユーザー確認済みの完全置換方針。旧建玉・決済データは移行されない）

### 9. 🔭 トレンド一覧タブ（セッション23で追加、**S24でチャート巡回ツールに作り直し**）

⚠️ **S97で画面ごと撤去済み**（「17. 🔭一覧タブ」参照）。以下は歴史的経緯。保存済みの market_view データ（`w.trend`・`judgeLog`・`snapshots` など）と端末間マージは残っており、画面から読み書きしないだけ。

**ユースケース（S24で明確化、S25で銘柄拡張）**: 手法がトレンドフォローなので、トレードの最初の工程は**「トレンドが発生している通貨を探すチャート巡回」**。監視28ペア（S25で仮想通貨6種を追加）を**1日約4回**見るが、都度長い時間はかけられない。**チャートを一目見て記録し、次へ**を最優先に設計されている。

巡回で記録するのは上位足ごとに3点：
1. **トレンド方向** — ↗上昇 / ↘下降 / ─レンジ
2. **EMA ZONE の色** — 緑 / 赤 / グレー
3. **グランビルの波** — 買①〜④ / 売①〜④

**S23からの変更点（なぜ作り直したか）**: S23 は「トレンド方向を並べて比べる」画面で、入力はアコーディオン展開が必要だった。22ペア × (展開→入力→閉じる) は1日4回の巡回に耐えず、EMAゾーンは記録すらできなかった。S24 で**アコーディオンを全廃し、行内で全項目をタップ**する形に変更。

**データモデル**:
```js
w.trend = { d: {state, zone, granville}, h4: {...}, w: {...}, mn: {...} }
// state: '' | 'up' | 'down' | 'range'
// zone:  '' | 'green' | 'red' | 'gray'      ← S24追加（EMAゾーンの色）
// granville: '' | '1'…'8'（1〜4=買い / 5〜8=売り）
w.trendAt = ISO文字列   // ← S24追加。ペア単位の最終更新時刻（鮮度表示用）
```
⚠️ **既存の `checksHigher.granville` とは完全に別データ**。ボードの「上位足」はユーザーが選んだ任意の1つ（週足〜1時間足）なのに対し、一覧は1時間足・4時間足・日足（＋任意で週足・月足）を固定枠で持つため意味が異なる。**CSV・トレード記録・統計には一切影響しない**（`CSV_HEADERS` に `trend` は入らない）。

**時間足（S24、S57で1時間足を追加）**: `MV_TREND_TFS` は1時間足・4時間足・日足・週足・月足の5本（表示順もこの並び）。うち `optional: true` の**週足・月足は既定で非表示**で、ツールバーのトグルで出す。表示設定は市場データではなく専用キー `mochipoyo_trend_tfs_v1` に持つ（端末ごとの表示設定にすぎないため）。

**並び順＝選択した時間足のアラート発生時刻順（S67、S44のエントリー圏距離順を置き換え）** — ツールバーの1H/4H/D/Wボタン（`trendSortTf`）で選んだ足の`w.alerts[tf].at`が新しい順。カード上のアラートバッジをタップした瞬間にもこの基準足へ切り替わる（`mvToggleAlert()`）。アラート未発生のペアは末尾に沈む。旧「エントリー圏までの距離」（`pairEntryDistance()`の昇順、S44でS32のGO/WAIT/NO判定を置き換えたもの）は並び順としては撤去したが、関数自体は波マップの圏内強調・🎯根拠ボタンの色分けで使い続けている。詳細は下記「11. エントリー圏で並べる」を参照（並び順以外の用途は無変更）。

⚠️ **`pairEntryDistance()`（波マップ・🎯チップが見る圏内判定）が見るのは `MV_TREND_DEFAULT_TFS`（1時間足・4時間足・日足、S57で1時間足を追加）だけ**。週足・月足は表示トグルで出入りするため、主軸に入れると「表示を切り替えただけで圏内判定が飛ぶ」。

**UI（S24、S44で判定バッジを撤去、S58で目線3択→手動GOに置換）**: 1ペア = **ヘッダ1行＋可視時間足ごとの入力行**の2バンド構成。
- **ヘッダ**: ペア名 / **🚩 GOボタン（S58）** / 鮮度チップ / アラートバッジ4つ / 🗑（巡回記録クリア）/ `→`（ボードへ）

  - ※ セッション58で目線3択（📈/〰/🔄）を撤去し、同じ位置に手動GOボタンを新設

**手動GOフラグ（S58、目線3択を置換）**: ペア名の直後の `GO` ボタン1つ。**`pairEntryDistance()` の自動距離とは完全に独立した主観の優先度タグ**で、巡回中に「これは近々来る」と判断したペアへ1タップで印を付ける。ONのペアは一覧の最上位「🚩 GO」グループにまとまり、**再タップで解除するまで自動では消えない**（`mvClearTrend()` の🧹巡回記録クリアの対象外＝クリアしてもGOは残る）。書き込み口は `mvSetGo()`。ツールバーの「🚩 GOのみ」ボタンで絞り込める（`trendGoOnly`、他の絞り込みとAND条件）。
- ⚠️ **旧「目線3択」（S35、📈トレンドフォロー/〰レンジ/🔄RD逆張り）はS58で完全撤去**。S44で自動判定から切り離されて以降は絞り込みタグの役目しか無く、ユーザー要望によりGOフラグに置き換えた。旧データ（`w.mode`/`w.modeAt`）は読み書きしないだけでlocalStorageには残るが無害
- データは `w.go`（真偽値）/ `w.goAt`（端末間マージ用タイムスタンプ）。`mergePair()` で `judgeAt` と同じ形の last-write-wins マージ

**グランビル・ピッカー（S44で簡素化）**: チップをタップすると**グランビルの図を表示したモーダル**が開く。**記録経路は図のタップだけ**（「買①〜売④」の8ボタンと「売買8つすべて表示」は S44 で撤去 — タップで自動確定する今は二重入力にしかならないため）。読み取り表示は波番号ではなく**エントリー圏との距離**。方向が未記録・レンジのときはチップが `disabled`。`IMG_GRANVILLE` は**開いたときに初めて代入**して初回描画から外している。

**鮮度**: `w.trendAt` から経過時間を出し、**12h超で `.stale`（警告色）/ 36h超で `.cold`**。1日4回の巡回に対して「1回抜けた／1日抜けた」の目安。ツールバーの「🕐 未更新のみ」で絞り込める。**鮮度でソートはしない**。

⚠️ **最重要仕様1**: アラート・判定の処理本体は **`mvToggleAlert()` / `mvSetJudge()` に切り出してボードと一覧で共有**している。`mvSetJudge()` は `judgeLog` への push を含み、振り返りタブの「アラート発生足別の判定統計」（`renderMvAlertStats()`）がこれを集計する。**どの画面から判定してもこの関数を通すこと**。直接 `w.judge` を書くと統計が壊れる。

⚠️ **最重要仕様2（S24）**: トレンド3項目の書き込みは **`mvWriteTrend()` が唯一の入り口**。`trendAt` の更新と、方向が消えた／反転したときのグランビル自動クリアをここで引き受けている。直接 `w.trend` を書くと鮮度表示と整合性が壊れる。

### 13. 波の位置タップ記録と 🗺 波マップ（セッション40で追加）

⚠️ **S97で画面ごと撤去済み**（「17. 🔭一覧タブ」参照）。以下は歴史的経緯。保存済みの market_view データ（`w.trend`・`judgeLog`・`snapshots` など）と端末間マージは残っており、画面から読み書きしないだけ。

**ユースケース**: 巡回で見ているチャートの頭の中には「買②を少し過ぎたあたり」「まだ買①の手前」という**連続的な位置**があるのに、記録は `買①〜売④` の8択（実際は方向で絞られた4択）しかなく、エントリーの早い/遅いが残らなかった。さらに全通貨を見渡して「今どこに何が溜まっているか」を掴む手段が無かった。

**やったこと**: グランビルの図をタップ面にして、**今のローソク足の位置を直接指す**。位置はそのまま残り、最寄りの公式ポジションが波番号として確定する。記録した位置は 🗺 波マップで全通貨まとめて見られる。

#### データモデル
`w.trend[tf]` に**文字列フィールド `wpos` を1つだけ**追加した。

```js
w.trend.d = { state: 'up', zone: 'green', granville: '2', wpos: '39.4,68.1', at: '...' }
```

- `wpos` = 画像に対する `"x,y"`（%・小数1桁）。**空文字＝ボタンで選んだだけの概算**、値あり＝図の上でタップした正確な位置
- `wx` / `wy` の2つではなく1つの文字列にした理由：①`mvEnsureTrend()` の「`trend[tf]` の全フィールドは文字列」という不変条件を壊さない（配列に `'wpos'` を1語足すだけで移行が済む）②x と y は必ず対で意味を持つので、片方だけ欠けた状態が構造的に作れない ③JSONバックアップでも人が読める
- アンカー座標は `MV_GRANVILLE_ANCHORS`（8点の % 座標）。ピッカーに薄い目印として重ねて出るので、図を差し替えて座標がズレたら目視で分かる

⚠️ **最重要仕様1**: **端末間マージ・CSV・統計・判定ロジックはすべて無変更**。マージは `trend[tf]` を**オブジェクトごと**差し替える（`if (B && ts(B.at) > ts(...)) out.trend[t.k] = B;`）ので、中に新フィールドを足しても同期コードは1行も触らなくてよい。`setupVerdict()` が読むのは `state / zone / granville` の3つだけなので GO/WAIT/NO も動かない。CSV は元から `w.trend` を見ない。

⚠️ **最重要仕様2**: **スナップ候補は必ずピッカーのグリッドに出ている選択肢と同じ集合**にする（`gvCandidates()`）。`mvWriteTrend()` は方向と逆 side のグランビルを自動で消すので、↗ の記録中に売りの波へスナップさせると**保存した瞬間に消える**。候補を絞ることで構造的に起こらなくしている。「売買8つすべて表示」を ON にすると候補も8つに広がり、そのときは既存仕様どおり自動クリアが効く。

⚠️ **最重要仕様3**: `wpos` の後始末は `mvWriteTrend()` の `if (!cur.granville) cur.wpos = '';` 1行だけ。granville が消える経路がそこ1箇所なので、方向の反転・レンジ化・クリアのすべてが自動で拾える。

⚠️ **最重要仕様4**: `.gv-fig` は**画像の実寸比を `aspect-ratio` に張って `object-fit` を使わない**。`object-fit: contain` のままだと「要素の箱」と「実際に絵が描かれる領域」がズレ、レターボックスの余白ぶんだけ重ね物が浮く（＝タップ座標が全部ズレる）。比率は `naturalWidth/naturalHeight` から JS が入れるので、図を差し替えても崩れない。

#### ピッカー（`💰 波?` チップから開く）
- 図の上をタップ → マーカー（リング＋十字）が出て、`買② 押し目` のようにスナップ結果を必ず言語化して表示する

### 14. 波マップの日次記録・単一銘柄モード（セッション42で追加）

⚠️ **S97で画面ごと撤去済み**（「17. 🔭一覧タブ」参照）。以下は歴史的経緯。保存済みの market_view データ（`w.trend`・`judgeLog`・`snapshots` など）と端末間マージは残っており、画面から読み書きしないだけ。

**ユースケース**: S40 で波の位置が残るようになったが、波マップは「今」しか見られず**昨日・一昨日と比べて波がどう動いたか**を追えなかった。また同じ銘柄の日足と4時間足を1枚に並べる手段が無かった。

#### 日次スナップショット（`snapshots` を再利用）

```js
const WM_KIND = 'wavemap';
const WM_KEEP_DAYS = 30;
// { id: mvGenId('wm'), at: ISO, day: 'YYYY-MM-DD', kind: WM_KIND,
//   items: [{ p: 'USDJPY', t: 'd', g: '2', w: '36,62', s: 'go' }] }
```

保存先は market doc の `snapshots`（S28 のマージ表に「`id` で集合和・`at` 昇順」の行が既にある純追記ログ）。**だから同期コードは `wmPrune` の1行しか触っていない。**

- **記録の契機**: PWA はバックグラウンドで動けないので「毎日12時に自動保存」は原理的に不可。代わりに **🔭一覧タブを開くたびに今日の分を上書き**（`wmAutoSaveOnOpen()` → `setActiveTab()`）＋ 波マップの「📸 記録」ボタン
- ⚠️ **今日は常に上書き、過去日だけ凍結。** 「未保存なら保存」にすると巡回前にタブを開いた瞬間に空のレコードが今日の分として確定し、その日の記録が丸ごと残らない。`items.length === 0` なら保存しない
- ⚠️ ペアは **`id` ではなく名前 `p`** で持つ（S28 が pairs をペア名で突き合わせるのと同じ理由。id は端末ごとに採番される）
- ⚠️ **`toISOString().slice(0,10)` は使わない**（UTC なので JST では朝9時に日付が変わり、朝の巡回と夜の巡回が別日になる）。`wmDayKey()` がローカル日付で切る

⚠️ **最重要仕様1（プルーンの2つの落とし穴）**:
1. `saveMarket()` の縮小ガードのカウントから **wavemap を除外**すること。30日プルーンが1件でも削ると毎回「縮小」判定になり、`__bak` が「1秒前の状態」で焼き潰されて復元ボタンが無力化する
2. `mergeDoc()` の**マージ結果にも `wmPrune` を掛ける**こと。`mergeLog` はトゥームストーン無しの集合和なので、片方が落とした古い記録が同期でそのまま戻り、落とす→戻るを永久に繰り返す。日付は決定的なので両端末が同じ集合に収束する
3. `wmPrune` は **`kind !== WM_KIND` を無条件 keep**（既存の想定レコードを巻き込まない）

⚠️ **最重要仕様2**: `w.trend[tf]` のスキーマ・CSV・統計・GO/WAIT/NO 判定はすべて無変更。増えたのは `snapshots` の中身だけ。`BACKUP_SCHEMA` も据え置き（キー構成は変わらない）。

#### 日付比較と軌跡

`◀ / 今 / ▶` で日付を戻すと、選んだ日を実線ドット、**その前日を薄いドット（`.prev`）で重ね、動いたものだけ線で結ぶ**。

- ⚠️ **散らし処理のオフセットを前日レイヤーへ転写すること**（`wmScatter()` が返す → `wmApplyOffsets()`）。散らしは「同一セル内の件数と並び順」で角度が決まるので、当日と前日で件数が1件違うだけで**動いていないペアの点までズレ、実在しない軌跡線が引かれる**
- ⚠️ **軌跡線は SVG**（`#trendMapTrail`、`viewBox="0 0 100 100"` ＋ `preserveAspectRatio="none"`）。div + `transform: rotate()` は `.gv-fig` の `--gv-ar` 依存でリサイズごとに破綻する。**viewBox を潰して使うので `vector-effect: non-scaling-stroke` は必須**（無いと線幅が縦横で歪む）
- ⚠️ **ナビの目盛から今日を外す**（`trendMapNavDays()`）。今日の分は一覧タブを開くたびに上書きされる＝「今」とほぼ同じ内容なので、外さないと ◀ ▶ が「今」と「今日」の間で無意味に1段寄り道する。ライブ表示の前日レイヤーも同じ理由で今日を除外する
- ⚠️ **過去日では「未更新のみ」「🚩GOのみ」の絞り込みが効かない**（items が `p/t/g/w/s` しか持たず、`w.go` を運んでいないため導出できない。S58時点で `s` は既にS44から空文字専用のキーで実質未使用）。`#trendMapNote` に明記する — 黙って無視するとフィルタが壊れて見える。**🎯エントリー圏のみ**は座標（`w`）、カテゴリはペア名から導出できるので過去日でも効く
- ⚠️ 凡例の `data-map-goto` は id を要求するが過去日はペア名しか持たない。引けなければ（削除済みペア）`<button>` ではなく素のテキストで出す。押しても何も起きないボタンは S42-③ の「無反応」バグの再演

#### 単一銘柄モード

銘柄プルダウン（`#trendMapPairSelect`）で1つ選ぶと、**その銘柄の表示中の全時間足を1枚に重ねる**。

- ⚠️ **絞り込みは `trendApplyFilters()` に足してはいけない** — 🔭一覧タブと共有しているため一覧の表示まで変わる。`trendMapLiveEntries()` / `trendMapDayEntries()` の中で当てる
- ⚠️ **`pairStatus()` はペア単位なので、1銘柄では全足が同じ status 色になって用を成さない。** 色は `.gv-dot.tf-d` / `.tf-h4` / `.tf-w` / `.tf-mn` の足別に振り直し、記録の質（タップ＝実線／ボタン＝中空）は `.pt` に残す。ラベルもペア名ではなく足名にする
- 足タブは選択ではなく凡例になる（`disabled`）
- `openTrendMap()` で**日付・銘柄とも毎回リセット**（閉じて開いたら「今の全銘柄」に戻る）

**拡張性**: `WM_KEEP_DAYS` 1つで保持期間が変わる。`MV_TREND_TFS` に足を追加すれば `wmBuildItems()`・単一銘柄モード・足別の色（CSS に1行）すべてに乗る。

**スコープ境界**: 残すのは**波の位置の定点観測**まで。判定（GO/WAIT/NO）の履歴やトレード成績とは接続していない。

### 15. 🗺 波マップのエントリー圏（セッション43で追加）

⚠️ **S97で画面ごと撤去済み**（「17. 🔭一覧タブ」参照）。以下は歴史的経緯。保存済みの market_view データ（`w.trend`・`judgeLog`・`snapshots` など）と端末間マージは残っており、画面から読み書きしないだけ。

**ユースケース**: エントリータイミングは **買②③ / 売②③** と決まっている。GO 判定は「その波かどうか」までは見ていたが、S40 で残るようになった **`wpos`（図のどこをタップしたか）はどこにも効いていなかった**。同じ買②でも「ドンピシャ」と「まだ手前」が区別できない。

**やったこと**: 波マップに **エントリー水準の圏**（4つ）を敷き、**圏内に入っているタップ記録だけを強調**する。

```js
const GV_ENTRY_RADIUS = 10;                  // % 座標での半径
function gvEntryDistance(x, y) { … }         // 最寄りのエントリーアンカーまでの距離
// trendMapEntryOf() が返す1件に dist / hot が乗る
```

- 圏の波は**別配列を作らず `SETUP_GO_WAVES` をそのまま参照**する。GO の波を増減したときに波マップの圏だけ取り残されると、判定と見た目が食い違う
- 半径 10% の根拠：8アンカーの最近接距離が約 19.5%（`'3'`↔`'8'`）なので、その半分が「他のどのアンカーより近い」ことが保証される上限。**定数1つでチューニングできる**

⚠️ **最重要仕様1**: **距離の測り方は `gvNearest()` と必ず同じ**（% 座標の素の距離）。画像は横長なので幾何学的には x と y で縮尺が違うが、ここで補正すると「買②と表示されているのに買③の圏内」という食い違いが起きる。**スナップ結果との一致 > 幾何学的な正しさ。**

⚠️ **最重要仕様2**: **概算（ボタンで選んだだけ＝`wpos` 空）は圏内に数えない。** 概算の座標はアンカーそのものなので距離 0 になり、買②③・売②③を選んだ全件が無条件で圏内になってしまう。見たいのは実測位置なので圏外扱いにし、その旨を `#trendMapNote` と凡例の脚注に明記する。

⚠️ **最重要仕様3**: `.gv-ezone` は **width と height を同じ「%」で指定する**＝画面上は横長の楕円になるのが正しい。`.gv-anchor` の `aspect-ratio: 1/1`（画面上の正円）と違い、`gvEntryDistance()` が測るのは % 空間の距離なので、画面上の正円にすると圏の見た目と圏内判定がズレる。

⚠️ **最重要仕様4**: `trendMapEntryOnly` の絞り込みは **`wmScatter()` より前**に当てる。散らしは同一セル内の件数と並び順で角度が決まるので、絞った後の集合で計算しないと前日レイヤーへ転写するオフセットが噛み合わず、S42 と同じ「実在しない軌跡線」が出る。

⚠️ **最重要仕様5**: `.hot` は**当日レイヤーだけ**（`trendMapDotHtml` が `' prev'` を見て外す）。過去の位置まで光ると「今どこが圏内か」が読めない。

**表示**:
- 図の上に緑の圏4つ（`#trendMapZones`。軌跡線より上・ドットより下）
- 圏内のドットは `.gv-dot.hot` でリング＋太字ラベル
- `#trendMapMeta` に `n件（うち 🎯 m件）`
- **凡例の先頭に「🎯 圏内（n）」グループ**（`.grp.entry`）。距離の近い順に `USDJPY 買② 3%`。既存の波番号別グループは従来どおり全件を再掲する
- ツールバーに **`🎯 エントリー圏のみ`**（`#trendMapEntryOnly`）。`openTrendMap()` で日付・銘柄と同様に**毎回 OFF へリセット**

⚠️ 凡例の 🎯 グループは同じペアを波番号別グループにも再掲するので、**テストで凡例の件数を数えるときは `.grp:not(.entry)` で絞る**こと（S40 テストの2件はこれで直した）。

**スコープ境界**: CSV・端末間マージ・統計はすべて無変更。

※ **S44 で `gvEntryDistance()` は 🔭一覧の主軸に昇格した**（`pairEntryDistance()` が並び順・サマリー・絞り込み・行の 🎯 に使う）。同時に GO/WAIT/NO 判定そのものが廃止されたので、上の「GO 判定」への言及は S43 時点の記述として読むこと。波マップ側の仕様（最重要仕様1〜5）はすべて現行のまま有効。
